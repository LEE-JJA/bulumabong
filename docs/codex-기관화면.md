# 작업 지시: 부루마봉 기관 담당자 화면 만들기

이 문서는 이 저장소를 처음 보는 사람(또는 AI)이 혼자 작업할 수 있도록 쓴 지시서입니다. 끝까지 읽고 시작해 주세요. 모든 화면 문구와 커밋 메시지, PR 설명은 한국어로 씁니다.

## 0. 이 프로젝트가 무엇인가

부루마봉은 강원도 원주에서 **도움이 필요한 곳(요양원, 보육원, 복지관, 어르신)** 과 **봉사할 사람(원주권 대학생, 캠퍼스 근처 주민)** 을 잇는 웹 서비스입니다. 대학끼리 봉사 시간을 겨루는 지도 게임을 붙여 20대가 봉사를 이어가게 만듭니다.

흐름은 이렇습니다.

1. **기관 담당자**(복지관, 요양원 직원 등)가 봉사 요청을 올립니다. 앱이 어려운 어르신은 전화로 요청하고, 담당자가 메모를 넣으면 AI가 요청 카드로 정리합니다.
2. **학생**이 요청을 보고 신청합니다. 요청마다 필요한 인원(정원)이 있고, 차면 마감됩니다.
3. 봉사가 끝나면 **담당자가 6자리 확인 코드를 발급**해 학생에게 알려 줍니다. 코드는 시설·요청·날짜·실제 봉사 시간에 묶여 있습니다.
4. 학생이 코드를 넣으면 **서버가 확인**하고 점수가 들어갑니다. 점수로 원주 지도의 구역마다 1위 대학 건물이 올라갑니다.

지금은 학생 화면(`index.html`) 안에 담당자 기능이 작게 끼어 있습니다. **이번 작업은 담당자 기능을 별도의 기관 담당자 화면(`org.html`)으로 옮기고 제대로 만드는 것**입니다.

## 1. 저장소 구조 (꼭 먼저 읽을 것)

외부 npm 패키지가 하나도 없습니다. Node.js 18 이상만 있으면 됩니다. **패키지를 새로 추가하지 마세요.**

| 파일 | 하는 일 |
|---|---|
| `index.html` | 학생 화면 전부. HTML, CSS, JavaScript가 한 파일에 들어 있음(약 400KB). 원주 지도 데이터 `const DATA = {...}`와 캠퍼스 그림 `const IMG = {...}`가 각각 아주 긴 한 줄로 들어 있으니 그 두 줄은 건드리지 말 것 |
| `api/brief.js` | `POST /api/brief`. AI(Amazon Bedrock) 호출. `{ facts }`를 보내면 봉사 브리핑 문장, `{ memo }`를 보내면 전화 메모를 요청 카드 `{ request: { title, hours, digital } }`로 정리 |
| `api/verify.js` | `POST /api/verify`. 확인 코드 발급(`action: 'issue'`)과 확인(`action: 'check'`). 환경변수 `CODE_SECRET` 필요. 시설별 기관 키는 `CODE_SECRET`으로 계산됨(`facKey`) |
| `api/_limit.js` | IP당 1분 호출 제한. 위 두 API가 같이 씀 |
| `server.js` | 로컬 서버. `node server.js` → http://localhost:3000. **지금은 `/api/brief`, `/api/verify` 말고는 모든 주소에 `index.html`을 돌려줌** |
| `test.js` | `node test.js` → `ok`. API 입력 검사, 개인정보 가리기, 확인 코드, 화면 스크립트 문법 검사 |
| `README.md` | 기획, 점수 규칙, 실행법 |

### index.html에서 알아야 할 것 (검색어로 찾으세요)

- **시설 목록**: `DATA.facilities`. 각 항목은 `{ id: 'f1', name: '신림 솔바람요양원', type: '요양원', district: '신림면', lon, lat, x, y }`. id는 `f1`~`f21`. `type`은 요양원, 보육원, 장애인복지관, 지역아동센터, 노인복지관, 무료급식소, 푸드뱅크 중 하나.
- **시연 모드**: `const DEMO = location.hash === '#test'`. 시연 모드에서는
  - 저장 키가 `ttbb.`에서 `ttbb.demo.`로 바뀝니다(`sk()` 함수와 `store` 객체).
  - 요청 날짜가 모두 오늘이 됩니다.
  - 확인 코드를 서버 대신 브라우저의 `demoVerify()`로 발급·확인합니다(기관 키 필요 없음).
- **요청 목록**: `const REQS`. 각 요청의 모양:

  ```js
  {
    id: 'rf1_0',        // 영문·숫자·_- 만, 40자 이하 (api/verify.js가 이 형식만 받음)
    fid: 'f1',          // 시설 id
    title: '말벗하며 산책 동행',
    hours: 2,           // 요청한 봉사 시간 1~8
    digital: false,     // 디지털 동행(스마트폰·키오스크 돕기) 여부
    src: 'org',         // 'org' 기관이 직접 | 'phone' 어르신 전화를 기관이 대신 | 'center' 주민센터가 대신
    date: '2026-11-18', // 봉사 날짜 YYYY-MM-DD
    when: '11월 18일 (수) 14시', // 화면에 보이는 날짜 글자
    need: 3,            // 정원
    filled: 1,          // 이미 신청한 다른 사람 수
    mine: 1794417000000 // 이 브라우저에서 만든 요청이면 만든 시각(최근 것이 위로)
  }
  ```

  시연용 요청은 코드로 만들어지고, 사용자가 만든 요청은 `store.get('ttbb.reqs')`에서 읽어 `REQS` 앞에 붙습니다. `openSlots(r)`이 남은 자리를 계산하고, `isPast(r)`이 지난 요청을 닫습니다.
- **지금의 담당자 기능**: `id="req"` 구역 안의 `<details class="memo">`. 그 안에 `memoForm`(전화 메모 → 요청 카드)과 `issueForm`(확인 코드 발급)이 있고, 함수는 `addMemoReq`, `renderIssueReq`, `issueCode`, `callVerify`, `demoVerify`, `localCard`입니다.
- **개인정보 가리기**: `const PII = [...]`와 `maskPII()`. **`api/brief.js`에도 똑같은 블록이 있고, `test.js`가 두 블록이 글자 하나까지 같은지 검사합니다.** 규칙을 바꾸면 모든 사본을 같이 바꿔야 합니다.
- **화면 스타일**: `:root`의 CSS 변수(`--ground`, `--chalk`, `--chalk-2`, `--chalk-3`, `--rule`, `--ginkgo`, `--danger`, `--display`, `--body`)와 `.sec`, `.sec-head`, `.form`, `.field`, `.btn`, `.btn.line`, `.btn.small`, `.fine`, `.err`, `.tag`, `.req` 클래스. 글꼴은 제목 Black Han Sans, 본문 IBM Plex Sans KR(Google Fonts).

## 2. 만들 것

### 2-1. 새 파일 `org.html` (기관 담당자 화면)

`index.html`과 같은 방식(한 파일, 인라인 CSS·JS, 외부 패키지 없음)으로 만듭니다. 디자인은 `index.html`의 색, 글꼴, 클래스 이름을 그대로 가져와 같은 서비스처럼 보이게 합니다.

**① 들어가기**
- 시설을 고르고(`DATA.facilities`와 같은 목록. `index.html`의 긴 `DATA` 줄을 복사하지 말고, 시설 21개의 `id, name, type, district`만 담은 작은 배열을 새로 만드세요) 기관 키를 넣습니다.
- 키 확인은 서버에서 합니다. `api/verify.js`에 `action: 'auth'`를 추가하세요: `{ action: 'auth', fid, key }` → 맞으면 `200 { ok: true }`, 틀리면 `403 { error: '기관 키가 맞지 않아요' }`. 기존 `facKey`와 `same()`(시간 일정 비교)을 그대로 쓰고, 기존 호출 제한도 그대로 적용합니다. `fid` 형식 검사도 기존과 같게.
- 확인된 키는 **`sessionStorage`에만** 둡니다(탭을 닫으면 사라짐). `localStorage`에 저장하지 마세요.
- 시연 모드(`org.html#test`)에서는 키 없이 들어갈 수 있습니다.

**② 우리 기관 요청 목록**
- 들어간 시설의 요청만 보여 줍니다. 위에 앞으로의 요청, 아래에 지난 요청과 마감한 요청(접어 두기).
- 각 줄: 제목, 날짜·시각, 시간, `신청 n/정원`, 디지털 동행 표시, 상태(모집 중 / 마감 / 지난 요청).
- 신청한 학생 명단은 **아직 만들지 않습니다**. 기록이 각 학생 브라우저에만 있어서 가져올 수 없습니다. 그 자리에 "신청한 학생 명단은 서버 저장소를 연결한 뒤에 보여 드려요" 같은 안내를 둡니다.

**③ 요청 올리기**
- 두 가지 방법을 탭이나 버튼으로 나눕니다.
  - **직접 쓰기**: 할 일(제목), 날짜, 시작 시각, 봉사 시간(1~8), 정원(1~10), 디지털 동행 여부.
  - **전화 메모로 만들기**: 지금 `index.html`의 `addMemoReq` 흐름을 옮깁니다. 메모를 `maskPII`로 가린 뒤 `POST /api/brief { memo }`로 보내고, 돌아온 카드(제목, 시간, 디지털 여부)를 **바로 올리지 말고 위 직접 쓰기 칸에 채워서 담당자가 확인·수정한 뒤 올리게** 합니다. AI가 안 되면 `localCard`처럼 정해 둔 제목으로 채웁니다.
- 검사: 제목 2~40자, 날짜는 오늘 이후, 시간 1~8, 정원 1~10.
- **제목은 저장 전에 `maskPII`를 한 번 더 거치고, 가린 자리(`[이름]`, `[전화번호]` 등 대괄호 표시)는 제목에서 빼세요.** 요청은 익명입니다. 어르신 성함, 연락처, 집 주소는 학생에게 보이는 곳 어디에도 나오면 안 됩니다.
- 새 요청 id는 `'o' + Date.now()`처럼 `api/verify.js`의 id 형식(영문·숫자·_-, 40자 이하)을 지키게 만듭니다. `src`는 직접 쓰기면 `'org'`, 전화 메모면 `'phone'`.

**④ 요청 고치기, 마감, 취소**
- 고치기: 제목, 날짜, 시각, 시간, 정원, 디지털 여부.
- 마감: 더 이상 신청을 받지 않음. 요청 객체에 `closed: true`.
- 취소: 봉사 자체를 하지 않음. `canceled: true`. 학생 화면에서는 "기관이 취소한 요청" 표시.
- 둘 다 확인 대화상자를 거칩니다.

**⑤ 확인 코드 발급**
- 지금 `index.html`의 `issueForm`을 옮깁니다. 요청을 고르고 **실제로 확인한 봉사 시간**을 골라 6자리 코드를 크게 보여 줍니다. 키는 ①에서 확인한 것을 그대로 씁니다.
- 날짜가 아직 안 된 요청과 취소된 요청은 발급할 수 없게 합니다.
- 코드 옆에 "학생에게 불러 주세요. 다른 요청이나 다른 시간으로는 쓸 수 없어요" 안내.

### 2-2. 저장: 지금은 브라우저, 나중에 서버

서버 저장소(AWS)는 **다음 작업**에서 붙입니다. 그래서 지금은

- 요청 읽기·쓰기를 **작은 함수 몇 개로만** 하게 만드세요. 예: `reqApi.list(fid)`, `reqApi.save(req)`, `reqApi.update(id, patch)`. 화면 코드는 `localStorage`를 직접 만지지 않습니다. 나중에 이 함수 속만 `fetch('/api/requests')`로 바꾸면 되게.
- 지금 이 함수들은 `index.html`과 **같은 저장 키** `ttbb.reqs`(시연 모드면 `ttbb.demo.reqs`)에 **같은 모양**으로 씁니다. 그러면 같은 브라우저의 학생 화면에 바로 보입니다.
- 이 한계를 화면에 숨기지 말고 README에 적으세요: "기관 화면에서 올린 요청은 서버 저장소를 연결하기 전까지 같은 브라우저의 학생 화면에만 보입니다."

## 3. 지켜야 할 것

- **익명**: 학생이 볼 수 있는 곳(요청 제목, 목록)에 어르신 성함, 연락처, 주소가 나오면 안 됩니다. 메모 원문은 저장하지도 보여 주지도 않습니다.
- **말투와 단어**: 화면 문구는 짧은 해요체. "점령, 뺏다, 빼앗다, 허물다, 무너뜨리다, 역습, 작전, 공격" 같은 말은 쓰지 않습니다(시설과 어르신을 차지하는 대상처럼 보이지 않게). 겨루는 것은 대학끼리의 봉사 시간입니다.
- **보안**:
  - 화면에 넣는 모든 글자는 `index.html`의 `esc()`처럼 HTML 이스케이프를 거칩니다(`innerHTML`에 사용자 입력을 그대로 넣지 말 것).
  - 기관 키는 화면에 다시 보여 주지 않고, 로그나 URL에 넣지 않습니다.
  - 비밀값(`CODE_SECRET`, API 키)을 코드나 저장소에 넣지 않습니다.
- **접근성**: 모든 입력칸에 `<label>`, 오류 문구는 `role="alert"`, 발급된 코드는 `aria-live`. 키보드만으로 모든 기능을 쓸 수 있게.
- **화면 폭**: 375px(휴대폰)에서 가로 스크롤 없이. 데스크톱에서도 보기 좋게.
- **바꾸지 말 것**: 점수 계산, 확인 코드 계산 방식(`codeFor`, `facKey`), 호출 제한, 저장 키 이름, `DATA`/`IMG` 긴 줄.
- 정규식을 스크립트로 파일에 써 넣을 때 백슬래시(`\d`, `\D`, `\s`)가 빠지는 일이 이 저장소에서 여러 번 있었습니다. 편집 뒤 `node test.js`와 정규식 줄을 꼭 눈으로 확인하세요.

## 4. 확인 방법

1. `node test.js` → `ok`.
2. `CODE_SECRET=dev node server.js`를 띄우고, 다른 터미널에서 `CODE_SECRET=dev node api/verify.js key f1`로 f1의 기관 키를 받습니다.
3. http://localhost:3000/org.html 에서:
   - 틀린 키로는 못 들어감. 맞는 키로 들어감.
