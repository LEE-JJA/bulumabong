# 부루마봉: 원주권 대학 봉사 대항전 (프로토타입)

원주에서 도움이 필요한 곳(시설·어르신)과 봉사할 사람(대학생·주민)을 잇는 봉사 매칭 서비스입니다.
대학 대항전은 20대를 봉사로 다시 불러오는 엔진입니다. 원주권 대학끼리 원주 안에서 쌓은 봉사 시간으로 읍면동마다 1위를 겨룹니다.
부루마블처럼 1위인 구역에 우리 대학 건물이 서고, 2위와 점수 차가 벌어질수록 최대 5층까지 올라갑니다.
따라잡히거나 봉사가 끊기면 한 층씩 내려앉습니다.
봉사가 쌓일수록 반계리 은행나무가 물들고, 종강 때 시즌을 결산합니다.

## 기획 의도 (발표용 요약)

- 문제 1, 봉사의 입구가 무너졌다: 2024학년도 대입부터 개인 봉사 실적이 반영되지 않으면서 10대 봉사가 크게 줄었다. 의무로 시작한 봉사가 끝나면 20대에 이어갈 계기가 없다.
- 문제 2, 손이 필요한 곳은 따로 있다: 읍·면 지역 요양원·보육원은 멀고, 도움이 필요한 농촌 어르신 상당수가 도움을 못 받는다.
- 문제 3, 도움을 요청하는 것 자체가 디지털 장벽이다: 앱으로 봉사를 찾고 요청하는 구조는 디지털에 약한 어르신을 빼놓는다.
- 해결 1, 도움 요청 매칭: 시설과 어르신이 요청을 올리고(앱이 어려우면 전화 한 통, 복지관·주민센터가 대신 등록) 학생과 주민이 신청한다. 스마트폰 교실, 키오스크 연습, 병원 예약 앱 설정 같은 `디지털 동행` 요청을 따로 모은다.
- 해결 2, 부루마블식 대항전: 손이 부족한 곳일수록 점수가 커서, 경쟁하다 보면 저절로 면 지역 요양원·보육원으로 간다. 건물 층수와 내려앉음으로 꾸준한 봉사를 끌어낸다.
- 해결 3, 캠퍼스 혜택과 동네 가게: 캠퍼스 생활권(캠퍼스 근처에 살거나 일하는) 주민·직장인도 시민 서포터로 대학 팀에 들어오고, 대학은 학식·도서관·체육관·평생교육 혜택을 연다(RISE 지역 기여 성과). 동네 가게는 봉사자 할인으로 손님을 얻는다.
- 우리가 노리는 숫자는 전국 봉사 총량이 아니라 끊기는 구간과 빈 곳이다: 20대 첫 봉사 후 4주 안 재참여율, 면 지역·가산 시설로 간 시간 비중, 디지털 동행 건수, 시민 서포터 수.

## 바로 보기

- `index.html`을 브라우저로 열면 끝입니다. 설치할 것이 없습니다.
- 이 상태에서는 AI 서버가 없으니 봉사 브리핑이 규칙 기반 문장으로 나옵니다.

## AI(Amazon Bedrock)까지 켜서 보기

Bedrock은 AWS가 운영하는 AI 모델 서비스입니다. 이 앱에서는 `봉사 브리핑` 문장과 전화 메모 요청 카드를 Bedrock의 모델이 만듭니다. 숫자(점수 차, 필요한 시간)는 앱이 계산해서 넘기고, 모델은 그 숫자로 문장만 만듭니다.

1. 해커톤에서 받은 AWS 계정으로 콘솔에 로그인 → 리전을 `미국 동부(버지니아 북부) us-east-1`로 바꿉니다.
2. Amazon Bedrock 화면 왼쪽 메뉴의 `API keys` → `Long-term API keys` → `Generate`로 키를 만듭니다. 키는 한 번만 보이니 바로 복사해 둡니다.
3. 기본 모델은 Amazon Nova Lite(`us.amazon.nova-lite-v1:0`)입니다. 따로 신청 없이 쓸 수 있는 모델이라 기본값으로 정했습니다. Claude 같은 Anthropic 모델을 쓰려면 Bedrock 콘솔에서 사용 목적 양식을 한 번 제출해야 합니다.
4. Windows PowerShell에서 (Node 18 이상):

```
$env:AWS_BEARER_TOKEN_BEDROCK="복사한 Bedrock API 키"
node server.js
```

5. 브라우저에서 http://localhost:3000 을 열고 `브리핑 받기`를 누릅니다. 문장 아래에 `AI(Amazon Bedrock)가 쓴 문장이에요`가 보이면 연결된 것입니다.

그 밖의 설정 (보통은 안 바꿔도 됩니다):

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `BEDROCK_MODEL_ID` | `us.amazon.nova-lite-v1:0` | 다른 모델을 쓸 때. 미국 리전은 `us.`로 시작하는 ID를 씁니다 |
| `AWS_REGION` | `us-east-1` | 키를 만든 리전 |
| `OPENROUTER_API_KEY` | 없음 | Bedrock 키가 없을 때 대신 쓰는 OpenRouter 키 |
| `AI_PROVIDER` | 자동 | `bedrock` 또는 `openrouter`로 강제 지정 |
| `CODE_SECRET` | 없음 | 봉사 확인 코드용 비밀값. 아무도 모르는 긴 문자열. **없으면 봉사 인증(점수)이 되지 않습니다** |

키가 없거나 연결이 실패하면 규칙으로 만든 문장으로 자동 전환되고, 문장 아래에 그렇다고 표시됩니다. 시연이 끊기지 않습니다.

## 시연 순서 (2~3분)

**주소 끝에 `#test`를 붙여 시연 모드로 엽니다** (예: `http://localhost:3000/#test`). 시연 모드에서는 요청 날짜가 모두 오늘이고, 확인 코드를 서버 없이 이 브라우저에서 발급·확인합니다. 무대에서 인터넷이 끊겨도 시연이 이어집니다. AI 기능만 인터넷이 필요하고, 안 되면 규칙 문장으로 넘어갑니다.

1. 첫 화면에서 `원주권 대학생`을 고르고 팀을 고르면 지도 위 건물들이 한 층씩 올라갑니다.
2. `도움 요청` 아래 `기관 담당자`를 열고 전화 메모를 적은 뒤 `요청 카드 만들기`를 누릅니다. 예: "김영자 할머니 010-1234-5678, 병원 예약 앱 설치를 도와 달라고 하심". AI가 할 일, 시간, 디지털 동행 여부를 정리한 요청이 **익명으로** 맨 위에 올라옵니다. 이름과 전화번호가 빠진 것을 보여 줍니다.
3. 학생으로 돌아와 그 요청(또는 요양원·보육원 요청)에 `신청하기`를 누릅니다. 정원이 차면 `마감`이 됩니다.
4. `봉사 브리핑`의 `브리핑 받기`: 가장 빨리 1위가 될 수 있는 구역과 가장 위태로운 우리 건물을 알려 줍니다.
5. 봉사를 마쳤다고 치고, 다시 `기관 담당자`의 `봉사 확인 코드 발급`에서 그 요청과 실제 시간을 골라 6자리 코드를 받습니다(시연 모드에서는 기관 키가 필요 없습니다).
6. `봉사 인증`에서 신청한 요청을 고르고 코드를 넣으면 점수가 들어가고 지도에서 우리 건물이 올라갑니다. 시간을 부풀리면 코드가 맞지 않는다는 것도 보여 줄 수 있습니다.
7. 구역을 눌러 `다음 층까지`, `위험`, `1위 되기`를, 시설을 눌러 `보육원은 두 번째 방문부터`, `다시 온 봉사 ×1.2`를 보여 줍니다.
8. 나머지 장면(다른 대학 추격, 한 주 흐르기, 시즌 결산)은 `시연 모드` 패널 버튼으로 보여 줍니다. 시간이 남으면 순위의 `1인당`, `봉사 혜택`, `원주 봉사패스`.

## 시연 모드

- 주소 끝에 `#test`를 붙여 열면 시연 모드로 시작하고 패널이 열립니다. 시연 모드에서는
  - 요청 날짜가 모두 오늘입니다.
  - 확인 코드를 서버 없이 이 브라우저에서 발급·확인합니다. 기관 키가 필요 없습니다. 보안 기능이 아니라 무대용입니다.
  - 기록은 실제 기록과 따로 저장되고, `내 기록`의 `시연 기록 지우기`로 지웁니다. `#test` 없이 열면 실사용 화면이고 시연 기록은 보이지 않습니다.
- `#test` 없이 연 화면에서도 오른쪽 위 `시연 모드`로 패널을 열 수 있지만, 이때는 장면 버튼만 쓰고 인증은 실사용 흐름(서버 확인)을 따릅니다.
- 단풍 진행 슬라이더와 `새잎 / 짙은 초록 / 물드는 중 / 샛노랑` 버튼: 은행나무 색을 바로 바꿉니다.
- `구역 1위 장면`: 우리 대학이 가장 적은 시간으로 1위가 될 수 있는 구역에서 우리 건물이 올라갑니다.
- `다른 대학 추격 장면`: 2위 대학이 따라와 우리(또는 가장 높은) 건물이 한 층씩 내려앉고 1위가 바뀝니다.
- `한 주 흐르기`: 열린 요청에 아무도 가지 않은 구역의 건물이 한 층씩 내려앉고, 0층이 되면 빈 부지가 됩니다. 여러 번 누르면 계속 내려앉습니다.
- `시즌 종료 장면`: 잎이 다 물든 뒤 떨어지고, 우승 대학 색과 은행잎 노랑 폭죽이 터지면서 시즌 결산 화면(1~3위)이 뜹니다. 실제 서비스에서는 종강(12월 18일)이 지난 뒤 처음 접속할 때 한 번 자동으로 뜹니다.
- `우승 표식 바로 보기`: 결산 1위 대학 캠퍼스에 하얀 크롭서클 표식이 그려지고, 시 경계가 그 대학 색으로 빛납니다. 이 표식은 다음 시즌 결산까지 남습니다.
- `처음 상태로`: 시연으로 바꾼 값을 모두 되돌립니다. 시연 값은 내 기록에 남지 않습니다.

## 봉사 시간 인증: 지금과 실서비스 계획

- 지금: 기관이 발급한 확인 코드를 서버(`api/verify.js`)에서 확인합니다. 데이터베이스 없이 비밀값(`CODE_SECRET`) 하나로 동작합니다.
  1. 운영자가 시설마다 기관 키를 만들어 담당자에게 따로 전합니다: `node api/verify.js key <시설 id>` (`CODE_SECRET`을 환경변수로 넣고 실행)
  2. 담당자는 `도움 요청` 아래 `기관 담당자`를 열고 기관 키로 6자리 확인 코드를 받아 학생에게 알려 줍니다. 코드는 요청, 날짜, 실제로 확인한 봉사 시간에 묶여서 다른 요청이나 부풀린 시간으로는 통과하지 않습니다.
  3. 학생은 `봉사 인증`에서 신청한 요청을 고르고 같은 시간과 코드를 넣습니다. 서버가 확인하면 점수가 들어가고 영수증(receipt)이 기록에 남습니다.
  4. 요청 날짜가 되기 전에는 인증할 수 없고, 날짜가 지난 요청은 새로 신청할 수 없습니다.
- 아직 못 막는 것: 같은 코드를 정원보다 많은 사람이 쓰는 것(누가 썼는지 저장할 공용 저장소가 없음), 점수 계산이 브라우저에서 이뤄지는 것. 공용 저장소가 생기면 영수증으로 중복을 막고 점수를 서버에서 계산합니다.
- 공용 저장소를 붙일 때 같이 할 것: 서버가 아는 요청 id에만 코드를 발급·확인하기(지금은 요청 id를 지어내 대상마다 10번씩 시도할 수 있음), 학생마다 다른 코드로 바꿔 남이 일부러 틀려 요청을 잠그지 못하게 하기, 오답 횟수를 서버 여러 대가 함께 세기.
- 1365·VMS와는 아직 연동하지 않았습니다.
- 공개 API로 가능한 것: 공공데이터포털의 `행정안전부_봉사참여정보서비스_GW`(1365 봉사 모집 정보)로 원주 지역 실제 봉사처·일감을 지도에 띄울 수 있습니다.
- 개인 봉사 실적: 1365·VMS 실적은 기관 담당자가 시스템에 등록하는 구조이고, 개인 실적을 외부 서비스가 조회하는 공개 API는 찾지 못했습니다. 그래서 단계별로 갑니다.
  1. 활동확인서 업로드: 학생이 1365·VMS에서 발급한 확인서를 올리면 AI(Bedrock)가 기관명·날짜·시간을 읽고, 운영자가 확인합니다.
  2. 기관 QR 체크인·체크아웃: 제휴 기관 담당자 화면에서 QR로 출석과 시간을 확인합니다.
  3. 정식 연계: 한국중앙자원봉사센터(1365), 한국사회복지협의회(VMS)와 협약해 실적을 받아옵니다.
- 개인정보는 이름·학교·봉사 시간만 다루고 주민등록번호나 연락처는 받지 않습니다.

## 집계 규칙: 한 사람, 한 팀

캠퍼스 생활권 주민·상인을 대학 팀에 넣으면 생기는 중복과 거리 가산 오류를 막는 규칙입니다.

| 규칙 | 내용 | 프로토타입 |
|---|---|---|
| 한 사람은 한 시즌에 한 팀 | 재학생·교직원은 사는 곳과 상관없이 소속 대학 팀(학교 메일 인증). 시민 서포터는 재학생이 아닌 사람만 | 화면 안내 |
| 소속이 생활권보다 앞선다 | 지정면에 살며 연세대 미래캠퍼스에 다니는 학생은 연세 팀. 지정면 생활권 캠퍼스(상지대)의 시민 서포터로 중복 가입 불가 | 화면 안내 |
| 거리 가산 기준점 | 학생은 캠퍼스와 집 중 가까운 곳에서 잰다. 지정면 학생이 지정면 요양원에 가면 캠퍼스 기준 11.7km(×1.4)가 아니라 집 기준 2.1km(×1.0). 시민 서포터는 집(상인은 가게)에서 잰다 | 구현 |
| 캠퍼스 생활권 | 집(가게)에서 8km 안의 캠퍼스, 없으면 가장 가까운 캠퍼스. 여러 곳이면 하나를 골라 시즌 동안 고정 | 구현(고정은 실서비스) |
| 시민 점수 상한 | 팀의 시민 서포터 점수는 그 팀 학생 점수의 절반까지만 시즌 순위에 반영. 상권이 큰 시내 캠퍼스로 쏠리는 것을 막는다 | 실서비스 |
| 신분이 바뀌면 | 졸업·휴학·전학은 다음 시즌부터 바뀐 신분으로 | 실서비스 |
| 개인정보 | 사는 곳은 읍면동까지만 받는다 | 구현 |

## 점수 규칙

| 항목 | 내용 |
|---|---|
| 기본 | 신청한 요청으로 한 봉사 1시간 = 1점. 요청한 시간까지만 셈 |
| 정원 | 요청마다 필요한 인원이 있고, 다 차면 마감. 정원 밖 봉사는 점수가 없음 |
| 시설 가산 | 요양원·보육원 ×1.5, 장애인복지관 ×1.3, 노인복지관 ×1.2, 지역아동센터·무료급식소·푸드뱅크 ×1.0 (지역아동센터는 행정 보조 봉사 위주라 가산 없음) |
| 거리 가산 | 내 캠퍼스에서 3km 미만 ×1.0, 3~8km ×1.2, 8km 이상 ×1.4 (원주 안에서만) |
| 아동 시설 | 보육원은 같은 시설 두 번째 방문부터 시설 가산 ×1.5. 처음 온 사람은 ×1.0 (한 번 오고 끝나는 봉사가 아이들에게 부담이라) |
| 다시 온 봉사 | 같은 시설에 4주 안에 다시 오면 ×1.2 |
| 기록만 | 신청하지 않은 봉사, 원주 밖 봉사는 내 기록에는 남지만 대항전 점수에는 들어가지 않음 |
| 상한 | 하루 최대 8시간 |
| 구역 1위 | 구역 안 시설 점수 합이 가장 높은 대학이 그 구역에 건물을 세움 |
| 층수 | 2위와 점수 차 0점 이상 1층, 3점 2층, 6점 3층, 12점 4층, 24점 이상 5층 |
| 내려앉음 | 2위가 따라오면 층이 줄고, 그 구역 시설이 요청을 올렸는데 한 주 동안 아무도 가지 않으면 한 층씩 내려앉음. 열린 요청이 없으면 봉사가 없어도 그대로(시설이 원하지 않는 방문을 부르지 않으려고). 0층이면 빈 부지(1위 구역 수에서 빠짐) |

층 기준과 한 주 감소는 `index.html`의 `FLOOR_AT`, `idleWeeks`, 아동 시설과 다시 온 봉사 가산은 `CHILD_TYPES`, `REPEAT_DAYS`, `REPEAT_MUL`에서 바꿀 수 있습니다. 실서비스에서는 인증 날짜로 주 단위 감소를 계산합니다. 프로토타입에서는 `한 주 흐르기` 버튼으로 시간을 흘려 보여 줍니다.

## 화면 디자인 원칙

- 겨루는 것은 대학끼리의 봉사 시간이지 시설이 아닙니다. 시설, 어르신, 아이를 빼앗거나 차지하는 대상처럼 쓰지 않습니다. "점령, 뺏다, 허물다, 무너뜨리다, 역습, 작전" 대신 "1위가 되다, 따라오다, 격차를 좁히다, 내려앉다"를 씁니다.
- 지도가 주인공입니다. 데스크톱에서는 지도가 화면 왼쪽을 꽉 채우고, 오른쪽은 카드 없이 가는 선으로만 나눈 한 줄 기둥입니다.
- 건물은 부루마블 보드처럼 비스듬히 내려다본 각도(아이소메트릭)로 그립니다. 원주 전체 보기에서는 읍·면 건물을, 시내 확대에서는 동 건물을 보여 줍니다. 건물 자리는 구역 안에서 시설 표식과 겹치지 않는 곳을 자동으로 고릅니다.
- 노란색은 은행나무와 시즌에만 씁니다. 버튼은 흰색(분필색), 대학은 각자의 색, 나머지는 어두운 숲색입니다.
- 큰 숫자, 그라데이션, 둥근 카드 반복은 쓰지 않았습니다. 시즌 진행은 퍼센트 막대 대신 은행나무 그림과 3월~12월 시간선으로 보여 줍니다.
- 글꼴: 제목은 검은고딕(Black Han Sans), 본문은 IBM Plex Sans KR.
